# Plan: v0.2 — Live grid

**Status:** Proposed · **Target:** v0.2.0 · **Owner:** FireBolt922

## Goal

Show every running emulator as a **live screen tile** in one window, like Orca's
multi-emulator view, while keeping emugrid lightweight.

Done means: with 6 emulators running, I open emugrid and see all 6 screens moving
in a grid, I can click one to enlarge it, and the app stays small and cheap.

## Where we are (v0.1)

- One window listing AVDs, running emulators (including TCP-connected ones such as
  Orca's `localhost:155xx`) and physical devices.
- Start / stop, auto-refresh every 3 s on a background thread.
- 3.1 MB release binary, ~97 MB RSS, 0% CPU idle. CI green on macOS / Windows / Linux.

## What we measured (2026-11-06, MacBook, emulator 37.1.11, 1080×2400 screens)

| Capture method | `emulator-5554` (SDK-started) | `localhost:15555` (Orca, over TCP) |
|---|---|---|
| `adb exec-out screencap -p` (PNG) | ~920 ms/frame, 1.4 MB | ~1100 ms/frame, 0.25 MB |
| `adb exec-out screencap` (raw RGBA) | ~630 ms/frame, 10.4 MB | **~13,900 ms/frame**, 10.4 MB |
| Emulator gRPC `streamScreenshot` | available on port 8554 | no discovery file found |

**Conclusions**

1. `adb screencap` tops out at **~1 fps**. Usable for thumbnails, not for "live".
2. Raw capture is unusable over TCP (10 MB per frame), so the fallback must be PNG.
3. SDK-started emulators expose a **gRPC server** (`grpc.port`, `grpc.token` in
   `~/Library/Caches/TemporaryItems/avd/running/pid_*.ini` on macOS; the matching
   temp dir on Windows/Linux). Its `streamScreenshot(ImageFormat)` pushes frames
   when the screen changes, can **scale on the emulator side**, and can send raw
   `RGB888` — so no video decoder, and small frames (a 270×600 RGB tile ≈ 0.5 MB).
   This is how Android Studio's Running Devices window works.

So v0.2 uses **two capture backends** behind one interface.

## Design

```
                 ┌──────────────── UI thread (egui) ────────────────┐
 devices::scan → │ list  ▸  grid of tiles  ▸  focused tile           │
                 │        ▲ latest frame per device (texture)        │
                 └────────┼──────────────────────────────────────────┘
                          │ channel: (serial, Frame{w,h,rgb})
          ┌───────────────┴───────────────┐
   GrpcStream (per emulator)        PngPoller (per device)
   streamScreenshot, scaled RGB888   adb exec-out screencap -p, ~1 fps
```

### New modules

| File | Responsibility |
|---|---|
| `src/capture/mod.rs` | `trait Capture` + `Frame { width, height, rgb: Vec<u8> }`; picks a backend per device; start/stop when a device appears/disappears. |
| `src/capture/grpc.rs` | Read emulator discovery `.ini` files → `{serial → (port, token)}`; open `streamScreenshot` with `Authorization: Bearer <token>`; request `RGB888` at tile size. |
| `src/capture/png.rs` | Background thread polling `adb exec-out screencap -p`; decode with the `png` crate; downscale to tile size. |
| `src/grid.rs` | Tile layout (columns from window width), tile = screen + name + status dot; click to focus; Esc / back to grid. |
| `proto/emulator_controller.proto` | Vendored subset of the emulator proto (only the messages/RPCs we use). |

`app.rs` gets a **List / Grid** toggle in the top bar. List view stays as is.

### Lightweight rules (non-negotiable)

- **Binary budget: ≤ 8 MB** release. Measured in CI; PR fails if exceeded.
- **No video decoder** in v0.2 (no ffmpeg, no openh264).
- Only stream what's visible: tiles scrolled out of view or a minimized window
  **pause** their stream.
- Frames are scaled **before** they reach us (gRPC) or right after decode (PNG);
  we only ever upload tile-sized textures to the GPU.
- Cap per-tile rate (default 15 fps gRPC, 1 fps PNG); focused tile may go higher.
- Idle (no emulators running): 0% CPU, same as v0.1.

### Dependencies to add

| Crate | Why | Size impact (to verify in step 2) |
|---|---|---|
| `tonic` + `prost` (+ `tokio`, current-thread) | gRPC client for the emulator | est. +1.5–2.5 MB |
| `png` | decode PNG fallback | est. +0.1 MB |

`tonic-build` needs `protoc` at build time; to keep `cargo build` zero-setup we
**commit the generated Rust code** and regenerate with a small `xtask` script only
when the proto changes.

## Steps (one PR each)

1. **Grid UI with PNG fallback** — `capture::png`, `grid.rs`, List/Grid toggle.
   Works for every device including Orca's, at ~1 fps. Ships value immediately.
2. **gRPC spike** — add tonic/prost, connect to one emulator, print frame rate and
   **measure binary size**. Go / no-go against the 8 MB budget.
   *If no-go:* keep PNG and look at a hand-rolled HTTP/2 client or the scrcpy route in v0.3.
3. **gRPC backend** — discovery on macOS/Windows/Linux, auth token, auto-select
   gRPC over PNG when available, reconnect when an emulator restarts.
4. **Performance pass** — pause off-screen tiles, rate caps, focused-tile mode,
   measure CPU/RAM with 1, 3, 6 emulators; record numbers in README.
5. **Size check in CI** — fail the build if the release binary exceeds 8 MB.

## Acceptance criteria

- [ ] Grid shows every running device with its live screen.
- [ ] SDK-started emulators update at ≥ 10 fps when the screen changes.
- [ ] Orca / TCP emulators and real phones update at ~1 fps (PNG fallback).
- [ ] Click a tile → enlarged view; Esc → back to the grid.
- [ ] Release binary ≤ 8 MB on all three OSes.
- [ ] With 6 emulators streaming: emugrid < 15% of one CPU core, < 250 MB RAM.
- [ ] No emulators running: ~0% CPU.
- [ ] CI green on macOS, Windows, Linux.

## Out of scope for v0.2

- Tapping / swiping / typing on tiles (v0.3 — `sendTouch` / `sendKey` over the same gRPC).
- Smooth streaming for Orca/TCP devices and real phones (v0.3 — scrcpy protocol, needs H.264 decode).
- iOS simulators.

## Risks

| Risk | Mitigation |
|---|---|
| tonic pushes the binary over budget | Step 2 is a go/no-go spike before we commit to it. |
| gRPC discovery path differs per OS / emulator version | Search all known temp locations; fall back to PNG silently. |
| Orca's emulators don't expose gRPC to us | They use the PNG fallback; v0.3 adds scrcpy for them. |
| Many PNG pollers saturate adb | One poller thread per device, sequential, back off when a capture is slow. |
| Emulator gRPC token handling changes | Read token from the discovery file each connect; also support `-grpc` without auth. |
